# Guardian Permission Centre

## Design goal
Security must feel like part of Guardian, not like a generic settings panel.

## Main view
Guardian is centered visually. Connected portals/apps/devices appear as nodes around Guardian.

Selecting a node reveals:
- Read
- Write
- Act
- Share
- Background Access
- Autonomy level
- Risk ceiling
- Last activity
- Active capability grants
- Revoke control

## Sensitive-action confirmation surface
Guardian must show five fields:
1. What I am about to do
2. What information will be used
3. Where the information will go
4. Whether this can be reversed
5. Why your approval is required

Buttons:
- Approve once
- Approve within current bounded rule (only when allowed)
- Deny
- Inspect details

## Visual constraints
- Keep visible Guardian presence.
- Do not replace Guardian with a chatbot window.
- Avoid generic blue settings/dashboard styling.
- Maintain STAARWAARDD futuristic luxury visual language.
